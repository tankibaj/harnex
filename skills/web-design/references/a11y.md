# Accessibility checklist for the web

last-checked: 2026-10-25
scope: HIG accessibility and VoiceOver rules translated to HTML/CSS/ARIA and merged with WCAG 2.2 AA; WCAG criterion in brackets.

## Accessibility ([HIG](https://developer.apple.com/design/human-interface-guidelines/accessibility))
- Aim: intuitive (familiar, consistent interactions), perceivable (no single channel: sight, hearing, touch, speech), adaptable (honor user settings, allow personalizing).
- Audit with an automated scan (axe, Lighthouse) plus a keyboard-only pass plus a screen reader pass (VoiceOver, NVDA); automation finds only part of the problems.

### Vision
- **Must** work at 200% browser zoom and 200% default font size, no loss of content or function [1.4.4]. Reflow at 320 CSS px wide without 2-D scroll [1.4.10].
- `rem` sizes; no fixed-height text containers; never `user-scalable=no` [1.4.4].
- Body 16-17 px; nothing under 11 px, prefer 12 px+. Scale meaningful icons with text (`em`).
- No thin weights: use 400+; thin custom faces need larger sizes.
- Contrast (check light, dark, and increased contrast):

| Item | Min ratio | WCAG |
|---|---|---|
| Text up to 17 px (normal) | 4.5:1 | 1.4.3 |
| Large text (18 pt = 24 px, or bold 14 pt = 18.66 px) | 3:1 | 1.4.3 |
| Bold text | 3:1 | 1.4.3 |
| UI component boundaries, icons, focus ring, state indicators | 3:1 | 1.4.11 |
| Custom small text, dark mode custom colors | aim 7:1 | HIG |

- HIG table is by point size (up to 17 pt: 4.5:1; 18 pt: 3:1; bold: 3:1); WCAG large text is 18 pt/24 px regular or 14 pt bold. Use the stricter reading for body text.
- Provide `@media (prefers-contrast: more)` token set when defaults miss the minimum.
- Re-check contrast over images, gradients, glass, hover, focus, disabled-looking-but-active states.
- **Never** color alone for info, errors, links, required, chart series [1.4.1]; add text, icon, shape, pattern. Inline links in text: underline or other non-color cue.
- Layout survives user text spacing overrides: line-height 1.5, paragraph spacing 2x, letter-spacing .12em, word-spacing .16em [1.4.12].
- Content on hover/focus (tooltips, menus) is dismissible, hoverable, persistent [1.4.13].
- Text as text, not images of text [1.4.5].
- Forced colors: support `@media (forced-colors: active)`; keep borders/focus visible (`outline` over `box-shadow`).

### Targets and spacing
- Primary touch targets 44x44 CSS px; never under 24x24 px [2.5.8] unless spacing offsets (24 px circle around target does not overlap another), inline link, or user-agent control.
- Padding between controls: about 12 px around bordered/filled controls; about 24 px around borderless ones, measured from visible edges.
- Enlarge the hit area without enlarging visuals: padding, or `::after` with `inset: -Npx`.
- Frequent actions need the simplest gesture; avoid custom multi-finger or multi-hand gestures.
- Every drag has a single-pointer alternative (buttons, menus) [2.5.7].
- Pointer: activate on up event (`click`), allow cancel by moving away [2.5.2]. Do not trigger on `pointerdown`.
- Visible label contained in accessible name (voice control: "click Search") [2.5.3]. Label every control so voice and switch users can name it.
- Single-pointer path-based or multipoint gestures (pinch, swipe) always have buttons [2.5.1].

### Keyboard and focus
- **Must** all functionality via keyboard alone, no trap [2.1.1, 2.1.2]. Custom shortcuts: **never** override browser, OS, or assistive tech shortcuts; single-character shortcuts need remap/disable or active-focus-only [2.1.4].
- Visible focus on every focusable element via `:focus-visible` [2.4.7]; ring at least 3:1 against adjacent colors [1.4.11]; **never** `outline: none` without replacement. Focus ring not hidden by sticky headers or overlays [2.4.11 Focus Not Obscured (Minimum)]; add `scroll-padding-block` for sticky bars.
- Focus indicator size/contrast target [2.4.13, AAA]: 2 px outline with 3:1 is a good default.
- Tab order = reading order = DOM order [2.4.3, 1.3.2]. Avoid positive `tabindex`; reorder DOM, not with `order`/`row-reverse` visual tricks.
- Native elements first (`button`, `a href`, `input`, `select`, `details`): free keyboard behavior.
- Composite widgets (tabs, menus, toolbars, radio-like groups, listbox, grid): one tab stop, arrows move inside (roving `tabindex="0"`/`"-1"` or `aria-activedescendant`); Home/End jump; Escape closes.
- Modal open: move focus inside (first control, or Cancel for destructive confirm), trap/inert the rest (`<dialog>.showModal()` or `inert`), Escape closes.
- Close: **restore focus** to the element that opened it (or the nearest logical one if removed).
- **Never** move focus without user action; no focus jump on load, async update, validation (except to the error summary after submit, or into a dialog the user opened) [3.2.1, 3.2.2].
- Focus on input must not cause context change [3.2.1]; changing a control's value must not auto-submit or navigate without warning [3.2.2].
- Skip link as first focusable element to `<main>` [2.4.1]; consistent navigation order across pages [3.2.3].
- Dragging, hover-only, and long-press features reachable by keyboard.
- Focus management on SPA route change: move focus to the new page `h1` or `<main>` (`tabindex="-1"`), update `document.title`.
- Redundant entry: do not ask again for data already given in the flow [3.3.7].

### Screen readers
- Semantic HTML first, ARIA second ("no ARIA beats bad ARIA"): `button`, `a`, `nav`, `main`, `ul`, `table`, `label`, `fieldset`/`legend`, `dialog`, `details`.
- Every interactive element: accessible name, role, state/value [4.1.2]. Names via visible `<label>`, content, `aria-labelledby`, then `aria-label`. System-generic names ("Button") are not enough: say what it does ("Delete draft"). Keep names current when UI changes.
- Icon-only controls: `aria-label` (or visually hidden text); icon itself `aria-hidden="true"`.
- Descriptions: `aria-describedby` for hints and errors.
- Images [1.1.1]:
  - Meaningful: `alt` says what the image conveys, not "image of"; do not repeat adjacent caption text.
  - Decorative: `alt=""` (or CSS background, `aria-hidden`).
  - Linked/functional image: alt = the destination or action.
  - Complex (chart, infographic, diagram): short alt naming it and its takeaway + long description nearby (visible text, `<figcaption>`, data table, `aria-describedby`). Expose chart interactions to keyboard and AT; offer the data as a table.
  - Group image + caption in `<figure>`/`<figcaption>`.
- Page title: unique, succinct, specific per page and view [2.4.2]. Section headings accurate [2.4.6].
- Headings: one `h1`, no skipped levels, structure not style [1.3.1]. Screen reader users navigate by headings; do not fake with bold `div`.
- Landmarks: `header`, `nav` (label if more than one: `aria-label`), `main` (one), `aside`, `footer`, `form`/`search` with names. Navigable by landmark [1.3.1, 2.4.1].
- Link text meaningful alone [2.4.4]; never "click here"; same text = same destination.
- Describe visual-only relationships in markup: grouping (`fieldset`, `role="group"` + label), order (real lists `ol`), table headers (`th scope`), required (`required` + text), current page (`aria-current`).
- Reading order follows DOM and `lang` [3.1.1]; mark foreign passages `lang` [3.1.2].
- Tell AT about visible content/layout changes [4.1.3]:
  - Status (saved, 3 results, copied): `role="status"` / `aria-live="polite"`.
  - Errors/urgent: `role="alert"` / `aria-live="assertive"`; use sparingly.
  - Live region must exist in DOM before content is injected.
  - Loading: `aria-busy` on region + status announcement; progress via `<progress>`/`role="progressbar"` with value.
- Form errors: tie to the field (`aria-describedby`, `aria-invalid="true"`), identify in text [3.3.1], suggest fix [3.3.3]; on submit with errors, focus the error summary or first invalid field.
- Inputs: `autocomplete` tokens for known purposes (name, email, address, cc) [1.3.5]; `type` and `inputmode` matched to data.
- Tabs, menus, disclosure, switch: correct pattern and states (`aria-expanded`, `aria-selected`, `aria-checked`, `aria-pressed`, `aria-current`).
- Hide decoration from AT; **never** `aria-hidden` on focusable elements; **never** `display:none`/`hidden` content you want read.
- Test with a real screen reader and rotor/element lists (headings, links, landmarks, forms): all must make sense out of context.

### Motion and media
- `prefers-reduced-motion: reduce`: reduce auto and repeated animation; swap slides/zooms for fades, no bounce, no parallax, no z-axis depth changes, no animating into blur (CSS in foundations-web.md Motion) [2.3.3].
- Anything that moves, blinks, scrolls or auto-updates for over 5 s: pause, stop, or hide control [2.2.2]. Carousels: no autoplay or visible pause.
- **Never** autoplay audio or video with sound; any audio over 3 s needs pause/stop/volume [1.4.2]. Offer a global opt-out for autoplay.
- Captions for prerecorded and live video [1.2.2, 1.2.4]; transcript for audio-only [1.2.1]; audio description or text alternative for video-only/visual info [1.2.3, 1.2.5]. Customizable caption styling when you render your own.
- Pair sound cues (success, error) with a visual cue; **never** audio alone for crucial info [1.1.1, 1.3.3].
- **Never** more than 3 flashes in any 1 second [2.3.1]; respect dimmed-flash/low-brightness preferences where available.
- Fast or blinking animation can cause dizziness and seizures: avoid.
- Motion actuation (shake, tilt) has a button alternative and can be disabled [2.5.4].
- Orientation: do not lock portrait or landscape [1.3.4].

### Cognitive
- **No** timed auto-dismiss of important UI (toasts with the only copy of a message, error banners, session logouts); explicit dismissal. Time limits: warn, allow extend (20 s warning, at least 10x extension) or turn off [2.2.1]. Toasts that carry Undo stay long enough to reach and operate (house heuristic: 8-10 s, pause on hover/focus).
- Simple, intuitive, consistent: standard controls over custom gestures; consistent identification and placement of repeated components [3.2.3, 3.2.4].
- Simple gestures with button alternatives: swipe-to-dismiss + close button; swipe-to-delete + delete in an edit/overflow menu; drag-reorder + move up/down [2.5.1, 2.5.7].
- Confirm hard-to-undo actions (delete account, pay, send); for destructive confirm ask once clearly, in plain words, naming the object and the consequence. Reversible actions use Undo instead (SKILL.md). Legal, financial, data-changing submissions: reversible, checked, or confirmed [3.3.4].
- Break multistep flows into one task per screen; show progress; keep entries when navigating back.
- Authentication without cognitive tests: allow paste, password managers, passkeys, no memorize-or-transcribe puzzles [3.3.8].
- Help in a consistent location [3.2.6]; plain language (writing.md).
- Never rely on memory: do not require remembering information from a previous step.
- Optional "reduce" modes: stable layout, no surprise content shifts; stable ads/layout without layout shift (CLS).

## VoiceOver ([HIG](https://developer.apple.com/design/human-interface-guidelines/voiceover))
- Alternative labels for every key element, custom ones included; descriptive, not generic; keep current when UI changes [4.1.2, 2.4.6].
- Meaningful images described by what the image itself conveys; captions read anyway. Charts and infographics: concise description and interactions exposed [1.1.1]. Decorative images excluded (`alt=""`, `aria-hidden="true"`).
- Page titles unique and succinct; section headings accurate [2.4.2, 2.4.6].
- Describe visual-only relationships (grouping, order, links); AT reads in DOM order, which must match the visual locale order [1.3.1, 1.3.2]. Group an image with its caption (`<figure>`).
- Notify AT of visible content and layout changes: live regions, focus to new content when user-initiated [4.1.3].
- Support navigation by headings and links (rotor equivalent: heading, link, landmark lists): real headings, real links [2.4.1].
- Web equivalents of platform assistive tech to test: screen reader (VoiceOver, NVDA, TalkBack), voice control, switch access, full keyboard access, pointer/zoom magnifier, forced colors.

## Quick review order
- 1. Keyboard-only pass of every flow (Tab, Shift+Tab, Enter, Space, Escape, arrows) [2.1.1, 2.4.3, 2.4.7].
- 2. Zoom 200% and 320 px width [1.4.4, 1.4.10]; text-spacing override [1.4.12].
- 3. Contrast in light, dark, increased contrast, forced colors [1.4.3, 1.4.11].
- 4. Screen reader pass: headings list, landmarks list, form controls list, one full task [1.3.1, 4.1.2].
- 5. Reduced motion on; autoplay off; no flashing [2.3.3, 2.2.2, 2.3.1].
- 6. Touch: targets 44 px, 24 px floor, gesture alternatives [2.5.8, 2.5.1].
